# 缓存与内存优化验收报告（2026-08-13）

## 结论

本轮已完成轨迹独立 Zstd 空间块、模型级字典、规范工件、内容寻址跨模型去重、三级模型运行态、后端统一字节缓存、前端压缩预热，以及首次缓存的独立 Builder JVM。原始表格及 MATSim 输入不改写；30 秒轨迹容器、10 秒播放窗口、1～2 秒快照、4096 米空间索引和前端二进制响应格式保持不变。

广州市真实抽样模型已完成一次 147,011,606 条 events 的全链路构建与缓存命中验收。相较旧缓存，模型缓存逻辑字节从 **6.720 GiB 降至 2.074 GiB（-69.13%）**；缓存命中的可视态切换从约 **4.089 s 降至 1.969 s（-51.85%）**；可视态 GC 后 Java 堆从约 **720 MiB 降至 276 MiB（-61.63%）**。

## 不变性与实现

### 轨迹

- 缓存版本升级为 `trajectory-v15`；每个 4096 米空间块是独立 Zstd 帧。
- 索引记录空间块、压缩偏移、压缩长度、原始记录数和包围盒；查询只读取并解压命中的块。
- 大模型轨迹记录为 16 字节：原始起点、原始终点、`vehicleIndex`、`linkIndex`。坐标、距离和模式从模型级 link 几何字典、车辆元数据字典恢复。
- 一条跨 30 秒边界的轨迹仍保存原始起止时刻；查询时才按窗口裁剪，避免边界位置和速度改变。
- 对外 GJTB v2 二进制格式不变，旧 v14 缓存仍可读；v15 未完成时不会把半成品发布为 ready。

### 规范工件与去重

- 线路、站点面板只保留轻量索引和 32 个详情分片；规范工件发布成功后删除旧的完整单体缓存。
- 人员轨迹分区库成为唯一规范工件，源派生单体在原子发布后删除。
- `canonical-artifacts.json` 声明每类数据当前唯一工件版本。
- SHA-256 内容寻址库位于缓存根目录 `.cas-v1/sha256`。APFS 等文件系统用硬链接；当前 ExFAT 缓存盘自动回退为相对符号链接，读路径和字节内容不变。原始输入目录不进入 CAS。

### 内存

- 模型运行态分为 `CATALOG`、`VISUAL`、`COMPUTE`。当前部署默认最多保留 1 个 COMPUTE 和 1 个 VISUAL 模型；LRU 自动降级，计算请求可按需恢复 COMPUTE。
- 缓存命中的 VISUAL 只加载公交子路网、公交时刻表和公交车辆。广州样本内存路网从 1,015,617 条 Link 裁剪到 202,957 条，完整道路显示由磁盘二进制瓦片保持不变。
- 首次缓存由一次性 Builder JVM 构建，主 Web JVM 只等待状态并继续服务；Builder 退出后其堆全部还给操作系统。
- 后端业务内存缓存统一进入按字节计量的全局 LRU；类库安全回退上限是 512 MiB，Docker/本机部署默认收紧为 256 MiB，并保留各分区上限。
- 前端 IndexedDB 以 gzip 字节保存预热结果。预热只验证/下载压缩字节，不创建完整 JS 对象或长期保留原始 `ArrayBuffer`；真正打开面板时才解压，网络不重复请求。

## 性能验收

三个真实轨迹样本的新查询 p95 分别为 0.207、0.255、0.247 ms，均低于 0.26 ms。与内存中未压缩块对比，Zstd 解压引入 0.11～0.13 ms 的 p95 CPU 开销；这是压缩必然成本，但远小于单帧预算，并未传递为可见卡顿。冷盘场景还会因读取字节减少而受益，本报告不把未单独测量的冷盘收益计入“变快”。

模拟 20 万条全市轨迹源、服务端空间裁剪后向前端交付 20,000 条轨迹（其中视口精确命中 10,100 条），连续 360 帧结果：

- 帧计算 p50 4.619 ms、p95 4.797 ms、p99 5.037 ms。
- 60 FPS 帧预算 16.667 ms，p95 余量 71.22%，理论 p95 上限约 208.5 FPS，通过 60 FPS 验收。
- 30 秒边界、1 秒/2 秒快照、10 秒窗口、视口命中、长 link、损坏修复和并发重建测试全部通过。

广州真实模型的服务端 HTTP 验收（USB ExFAT，8×8 个 4096m 空间块的高峰时段视口）：10 秒 `viewport.bin` 100 次平均 341.816 ms、p95 397.839 ms；1 秒 `frame.bin` 100 次平均 170.822 ms、p95 248.001 ms，全部 HTTP 200。HTTP 只为切块/跳转供给，连续 60 FPS 由已下载块的 Worker 插值，不是每帧回源。

## 自动化验收

- 前端：52 个测试文件、316 项测试全部通过；生产构建通过（3.06 s）。
- 后端：259 项测试中 251 项通过、6 项跳过、2 项失败。两项失败与改造前基线完全一致：
  - `RealDataServiceImplCommitEditsTest.vehicleCalculationAddsFleetFieldAndLeavesUnsavedRoutesEmpty`
  - `RealPopulationCacheEvaluationTest.stationPopulationCoverageSeparates300And500MeterResidents`
- CAS 已分别通过支持硬链接的本地文件系统测试和真实 ExFAT 缓存盘回退测试；两个相同 128 KiB 跨模型工件只保留一份物理内容，第二份复用率 100%。

## 文件系统口径与上线要求

逻辑字节已实测降低 69.13%，但本机 USB 盘是 ExFAT，其分配单元为 1 MiB，macOS 还会为数千个索引/符号链接生成 AppleDouble `._*` 伴生文件。因此本地 `du` 物理分配口径从 11,758,080 KiB 变为模型目录 11,526,144 KiB + 全局 CAS 4,813,824 KiB，没有体现逻辑压缩收益。这是本轮本地验收唯一未达标项，不能把“模型目录不跟随 CAS 链接”误报为物理节省。

生产缓存盘必须使用 ext4/XFS/APFS（建议 4 KiB 分配单元），不应使用 ExFAT。在该前提下，2.074 GiB 新逻辑工件和 CAS 硬链接才会转化为接近 69% 的实际盘占用降幅，且后续模型才能叠加跨模型去重收益。
