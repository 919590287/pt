# 平台全链路性能分析与优化报告（2026-07-16）

## 结论

本轮优化已覆盖平台首开、认证、模型首次触发、模型后续加载、模型目录轮询、前端资源解析和地图交互调度。改动仅调整加载顺序、请求复用、缓存就绪探测与渲染调度，没有修改地图图层样式、业务公式、采样扩算、接口返回结构或模型计算结果。

最明显的收益有三项：

1. 登录冷启动实测传输量从 890,499 B 降至 384,597 B，减少 56.8%。
2. 稳定模型状态不再每次轮询扫描外置磁盘；新实现热路径 1,000 次共 43.4 ms，约 0.043 ms/次。
3. 缓存准备不再解析 123.84 MB 的完整轨迹清单，改读 1.05 MB 轻量清单；同机通用 JSON 解析探针对比为 1.40 s → 0.03 s。

## 测量口径

- 前端：Vite 生产构建；Codex 内置 Chromium，关闭浏览器缓存后访问本地生产资源服务 `127.0.0.1:8088`。
- 后端：现有生产日志、真实模型目录与缓存目录；新代码通过 JShell 直接调用状态服务做微基准。
- 数据盘：`/Volumes/USB DISK/pt_data`；缓存盘：`/Volumes/USB DISK/pt_cache`。
- 浏览器 DCL 是本机单次冷样本，受本机调度影响，只用于方向性对比，不作为生产 SLA。

## 已实施优化

### 模型首次加载

- 路由守卫在异步地图和业务页面资源开始解析前就启动全局模型运行时。
- 目标方案模型列表优先获取，立即发送 `loadModel`；其他方案在后台补齐，不再阻塞目标模型。
- Element Plus 业务控件、地图壳、目标页面 chunk 和后端模型启动并行执行。
- 全局门禁、运行监测、换乘分析、场景对比和线网优化共用同一目录请求单飞。

### 模型后续加载与缓存

- `MatsimOutFile` 扫描阶段只发现配置路径；真正加载模型时解析一次并在实例内复用。
- 缓存准备的就绪判断改用 `manifest-lite.json`，不再读取完整轨迹明细。
- 模型状态增加 10 秒可失效快照；已就绪模型不再被周期巡检强制失效，源变更在重启、手动重建或首次状态校验时检测。
- manager manifest 只解析一次即可同时得到 `ready` 与 `generatedAt`，去掉重复读取。
- output 大小和是否包含 plans 合并为一次目录扫描，模型列表不再为 `cuttable` 再扫一遍 output。

### 平台响应与登录

- 登录、注册、改密不再重建模型注册表；用户名改名仍保留全量重建，因为该操作会真实改变模型目录键。
- 当前真实 6 模型目录扫描微基准为 176 ms，这部分已从每次认证成功路径移除。
- 已加载且缓存 ready 的模型不再被误判为过渡态，稳定页面目录心跳从 20 秒降为 100 秒。

### 前端下载、解析与交互

- 登录仅注册 `Button/Form/FormItem/Input` 四个必要控件；其余控件与 CSS 登录后按需加载。
- MapLibre CSS 下沉至地图布局，不再进入认证页面。
- 目录请求采用 750 ms 短时新鲜度和按方案 in-flight 单飞，重叠请求直接复用。
- 左侧面板 ResizeObserver 和地图 `styledata` 均改为每帧最多执行一次。

## 模型加载阶段的真实边界

### 首次载入已有缓存的模型

生产日志中，广州抽样模型基础加载分别出现 13,289 ms 和 14,637 ms。模型基础输入本身较大：

- `output_plans.xml.gz`：约 274 MB；
- `output_network.xml.gz`：约 29.5 MB；
- `output_transitSchedule.xml.gz`：约 8.35 MB；
- 另有车辆、设施与配置文件。

这些文件位于外置 USB 卷，MATSim 需要解压并构建对象图。为了保持人口、出行链和线路计算结果完全一致，本轮没有跳过 plans，也没有改为近似或抽样加载。因此本轮消除了重复配置解析、启动排队和缓存状态开销，但不会把真实 MATSim 场景解析伪装成毫秒级操作。

### 首次生成模型缓存

两个广州模型的 `output_events.xml.gz` 分别约 1.56 GB 和 1.83 GB。缓存冷启动必须流式消费 events，并生成轨迹、换乘、车速、人口和出行派生产物；这是首次缓存的主耗时。现有实现已经采用流式读取、分块二进制缓存、受控并行和后台单飞，本轮保留全部计算口径。

最有效的运营策略是模型发布后提前生成缓存，而不是让第一位用户承担 1.5–1.8 GB events 的首次处理。

### 后续页面切换

地图布局和高频页面继续使用 KeepAlive；模型目录、交互面板和二进制分片仍使用既有内存/磁盘缓存。本轮新增的跨页面目录请求单飞与 RAF 合帧进一步降低了切页和缩放时的主线程竞争。

## 仍需关注的部署风险

1. **外置卷稳定性是当前最大非代码风险。** 2026-07-16 19:10 与 20:59 的生产日志均出现 `/Volumes/USB DISK` `AccessDeniedException`，一次会让多个模型缓存任务同时失败。建议生产数据与热缓存迁移到稳定 NVMe/APFS 卷，至少保证缓存目录独立、可写且不会因 USB 休眠掉盘。
2. **业务地图包仍然重。** MapLibre 路由块约 1,247.29 kB / 332.51 kB gzip，ECharts 约 704.15 kB / 235.75 kB gzip。它们已不污染登录页，并按业务路由加载；继续拆分需结合真实设备 INP/FPS，避免改变首帧图层出现顺序。
3. **卸载后的模型重新解析仍受 300 MB 级压缩输入限制。** 若未来必须将 13–15 秒进一步压缩，需要引入带源文件指纹的场景快照或受内存预算约束的热模型 LRU。两者都会改变“卸载即释放内存”的资源语义，本轮未擅自实施。
4. **生产服务尚需重启后采集接口 P50/P95。** 代码级微基准已验证热状态路径，正式发布后应对 `/pt/scheme/modelList`、模型加载、route panel、station panel 记录至少 24 小时 P50/P95。
