# 线网优化模块设计方案（v2 全量重构）

> 2026-07-03 起草。本方案**完全替代**现有 `/scenarioedit` 模块的功能设计（现有代码中可复用的仅是技术件：多边形绘制、SHP/GeoJSON 上传解析、面板布局样式）。
>
> 一句话定义：**以一个已完成运行的仿真模型为"母本"，圈定研究区域，对区域内的公交线网 / 站点 / 路网 / 运营策略做一组修改，一键生成"基线 + 方案"两个 MATSim 模型并顺序运行，结果自动注册进模型库，供运行监测、客流分析、优化评估模块查看对比。**

## 1. 总体框架与页面布局

### 1.1 核心业务闭环

```mermaid
flowchart LR
    A[右上角选择母本仿真模型] --> B[地图圈定研究区域]
    B --> C[左面板编辑：线路/站点/路网/策略]
    C --> D[右面板修改清单<br/>可撤销/可编辑/自动存草稿]
    D --> E["生成仿真模型（向导）"]
    E --> F1[① 按区域切分母本<br/>→ 基线模型 input]
    F1 --> F2[② 应用全部修改项<br/>→ 方案模型 input]
    F2 --> F3[③ 顺序运行两个模型]
    F3 --> G[注册进模型库 + 构建缓存]
    G --> H[运行监测/客流分析单独查看<br/>优化评估做基线vs方案对比]
```

**方法论基石**：对比永远发生在"切分后的基线"与"切分后的方案"之间，二者共用同一份切分结果、同一份 config、同一随机种子，只差修改项本身。这样切分引入的边界误差在两侧**同向抵消**，对比结论可信。切分基线的绝对数值不与母本全市模型直接对比。

### 1.2 页面布局

沿用平台"左操作 / 右信息 / 中间地图"的既有语言（与数据管理、运行监测一致，含左右折叠页签、MCard2 卡片、顶部搜索）：

```
┌──────────────── MHeader 模块导航 ──────────────┬ 右上角：[方案区域▾][母本模型▾(仅仿真)] ┐
│ ┌─ 左侧·操作面板 ────────┐                      ┌─ 右侧·方案面板 ──────────────┐ │
│ │ 草稿：金洲片区方案A ▾   │                      │ 修改清单 (12)   [清空] [导出] │ │
│ │ ─────────────────────  │                      │ ┌──────────────────────────┐ │ │
│ │ ① 研究区域             │      地图画布         │ │ ➕ 新增线路「金洲环1」  ✎ ↺│ │ │
│ │   绘制 / 行政区 / 上传  │  母本线网 + 编辑叠加   │ │ ✏ B301 间隔 10→6min   ✎ ↺│ │ │
│ │   面积 12.4km² 线路38条 │  （新增=绿 修改=橙     │ │ ✖ 删除站点「南横村」   ✎ ↺│ │ │
│ │ ② 线网编辑             │    删除=红虚线）       │ │ …                        │ │ │
│ │  [线路][站点][路网][策略]│                      │ └──────────────────────────┘ │ │
│ │  （当前工具的参数表单）  │                      │ 校验：1 错误 2 警告  [详情]   │ │
│ │ ③ 生成仿真             │                      │ ───────────────────────────  │ │
│ │   状态/最近任务入口     │                      │ [      生成仿真模型      ]    │ │
│ └───────────────────────┘                      │ ─ 运行任务 ─                  │ │
│                                                 │ ▶ 基线 it.36/100  ▷ 方案 排队 │ │
│                                                 └──────────────────────────────┘ │
```

- **左侧面板 = 做动作**：三段式工作流（区域 → 编辑 → 生成），始终可见当前处于哪一步；选中某编辑工具后，左面板下半区变成该工具的参数表单。
- **右侧面板 = 看结果**：修改清单（本方案的唯一事实来源）、校验状态、生成按钮、运行任务进度。
- **地图 = 画布**：显示母本模型的路网/线路/站点图层（复用现有 tile / lineAll 数据通道），编辑效果以差异色叠加渲染，全部由右侧修改清单**派生**（清单删一项，地图叠加自动消失——这就是撤销的实现方式，无需独立 undo 栈）。

### 1.3 页面状态机

```
未选模型 → 模型加载中 → 待圈区域 → 编辑中 ⇄ 生成向导 → 任务运行中 → 完成
```

- 未选择/未加载母本模型时，左右面板置灰并给引导文案（"请先在右上角选择一个仿真模型"）。
- "任务运行中"不锁页面：任务在服务端排队执行，用户可以离开、可以继续编辑新草稿；右侧"运行任务"区常驻展示本人未完结任务。

### 1.4 与其他模块的关系

| 模块 | 关系 |
|---|---|
| 运行监测 / 客流分析 | 生成的两个模型出现在其右上角模型下拉里，可单独查看（含缓存构建，与普通模型无差别） |
| 优化评估（scenariocomparison） | 两模型写入 `pairId` 元数据，优化评估可自动配对做"基线 vs 方案"对比（P1 落地对比报告） |
| 配车测算 | 远期：方案模型的车队规模可送配车测算反推配车数（P2 展望） |
| 数据管理 | 不交叉；线网优化只读母本模型，不改真实数据 |

## 2. 母本模型选择（右上角）

- 复用运行监测页的方案/模型两级下拉（建议趁此把它抽成公共组件 `ModelPicker.vue`），但**去掉"仿真/真实"切换**——本模块固定 datasource=仿真。
- 下拉沿用现有能力：`/pt/scheme/schemeList` → `/pt/scheme/modelList`，显示 公开/私有、加载状态、缓存状态。
- 选择后自动触发 `loadModel`（沿用现有加载+轮询进度模式）；模型加载完成才允许圈区域和编辑，因为编辑的底图数据（线路、站点、路网瓦片）全部来自该模型。
- **母本资格校验**：母本必须有完整 `output_plans.xml.gz`（切分依赖它）。modelList 已有 `outputBytes` 等信息，后端补一个 `cuttable: boolean` 字段，不可切分的模型在下拉中置灰并注明原因。
- 切换母本时：若当前草稿有未生成的修改，弹窗提示（草稿与母本绑定，切换=切换到该母本下的草稿列表）。

## 3. 研究区域划定

### 3.1 三种圈定方式

| 方式 | 交互 | 说明 |
|---|---|---|
| **手绘多边形**（默认） | 地图逐点点击，双击或回车闭合；ESC 取消；顶点可拖拽微调、边中点可加点、右键删顶点 | 复用现有 scenarioedit 的临时图层绘制代码（DRAWING_SOURCE 三件套），补顶点编辑 |
| **行政区快选** | 下拉选择区/街道，边界自动作为研究区域 | 复用 `adminDistrictRange.js` 的边界数据与相交判定 |
| **文件上传** | SHP / GeoJSON 拖入 | 复用现有解析与投影转换（proj4） |

### 3.2 辅助参数

- **缓冲距离 bufferM**（默认 500m，高级选项 0–3000m）：切分时"区域 ∪ 缓冲带"才是实际保留范围，用于缓解边界效应（见 §8）。地图上以半透明外圈同时显示缓冲带。
- 多边形自相交实时检测（自相交则标红禁止确认）；面积上限提示（如 > 母本区域 60% 时提示"切分收益有限，建议直接全网修改"）。

### 3.3 确认区域后

- 地图：区域内要素正常显示，区域外整体压暗（利用现有 clip 工具做视觉聚焦）；
- 右侧面板顶部显示**区域概览卡**：面积、周长、区域内线路数 / 站点数 / 路段数、日均触达出行量估计（后端 `areaStats` 接口，基于母本缓存统计，见 §11.2）；
- 区域锁定：产生第一条修改项后，修改区域需二次确认（"重新圈定将重新校验全部修改项"→ 逐项重算 in/out 状态，越界项标警告而不是直接删除）。

## 4. 线网编辑工具（左侧面板）

左面板"② 线网编辑"下四个页签：**线路 / 站点 / 路网 / 策略**。每个工具是一种"地图交互模式"（互斥，顶部显示当前模式，ESC 退出）。所有编辑只产生**修改项**（追加进右侧清单），不直接改任何数据——真正的文件修改发生在生成阶段（§9）。

通用交互约定：

- **选中目标**：点击地图要素（重叠时弹出候选列表，复用数据管理页的 picker 弹窗模式）或顶部搜索框搜名称定位。
- **吸附**：画线/落点一律吸附路网。前端瓦片数据做粗吸附预览，落定后调后端 `snap` / `routing` 接口精确化（在母本 network 上计算，见 §11.2），避免前端瓦片精度不足。
- 编辑目标原则上限定在研究区域内（区域外要素点击时提示"不在研究区域内"，允许"仍要修改"的旁路以支持跨界线路的整体调整）。

### 4.1 线路页签

**新增线路**
1. 地图上依次点击锚点，后端沿"公交可行路网"（modes 含 bus/car 的 link）自动寻径串联，实时预览走向；支持拖动中间锚点局部改道；
2. 走向确定后，系统自动列出沿线 80m 内的既有站点（默认全选），可取消勾选、可"在此处插入新站"（顺手创建 `stop.add` 修改项并建立依赖）；
3. 参数表单：线路名称、双向/单向（双向默认按同走向反排站序，可分别微调）、服务时段（首末班）、发车间隔（单值或分时段表）、车型（从母本 transitVehicles 车型列表选，或引用新建车型）、平均运营车速（默认取沿线 link freespeed 的 min(·, 40km/h)，用于推算站间运行时分）、站点停靠时间（默认 30s）。
4. 提交 → 生成 `route.add` 修改项。

**修改线路**（选中既有线路后进入子操作菜单）
- **改走向**：在线路上点选"改线起点站/终点站"两个锚点，中段重新画走向（同新增的寻径交互），未动的首尾段保留；
- **调整停靠**：沿线站点复选（跳站/增停），不改几何；
- **截短 / 延长**：拖动首/末端到新的终点站（延长段走新增走向交互）；
- **改发车间隔**：单值或分时段表（见 §5 O1）；
- **改服务时段**：首末班时间；
- **换车型**：车型下拉。
- 每个子操作各生成一条独立修改项（同一线路多条修改项按顺序叠加应用），便于逐项撤销。

**删除线路**：整线删除或只删单方向。列出该线在母本中的日客流（来自缓存面板数据）作为决策参考。

### 4.2 站点页签

- **新增站点**：点击地图，吸附至最近可停靠 link（显示吸附示意）；命名；可选"同时插入某些线路的停靠序列"（弹出经过该 link 的线路列表勾选）。
- **修改站点**：移动位置（重新吸附，越 link 移动给警告）、改名、**合并站点**（框选/多选 2+ 站合并为 1，保留者可选，所有引用线路自动改引用）。
- **删除站点**：列出引用该站的全部线路及日上下客量；处理方式固定为"各线路跳站"（站序中移除，不改走向）。

### 4.3 路网页签

- **新增路段**：起点吸附既有节点（或落在 link 上自动打断插入新节点），逐点画折线到终点；参数：单向/双向、车道数、限速、通行能力（默认按车道数×1800pcu/h 估）、允许模式（car/bus/both）；长度按几何自动算。
- **删除路段**：点选 link（双向成对时询问删单向还是双向）；实时列出受影响对象：经过的公交线路（阻断性错误，必须先改线或确认自动重排）、母本中该 link 流量（提示背景交通影响）。
- **修改路段属性**：限速、容量、车道数、允许模式。
- **公交专用道**：选择一段连续 link（支持沿线路一键选取），两种实现方式二选一（表单里明示差异，默认 A）：
  - A. **新增平行专用道 link**（modes=pt，freespeed=原限速，capacity 按 1 车道），原 link 的 car 容量按扣除 1 车道折减——更接近真实"占用一条车道"；
  - B. **整段禁小汽车**（modes 去掉 car）——适合"公交专用路"。

### 4.4 策略页签

承载 §5 中"非画图类"的修改项（运营与政策类），以表单+目标选择器的形式录入，如分时段发车间隔批量调整、票价方案、大站快车向导等。向导类策略（快车、区间车、接驳环线）本质是"自动生成一组基础修改项"的宏，生成后仍以普通修改项形式进清单、可逐条撤销。

## 5. 优化策略库（全部可选修改项）

> 这是对"除了调线调站还能改什么"的完整回答。每项标注：落地的 MATSim 文件、实现要点、建议分期（P0=首版必做，P1=第二批，P2=远期）。

### A. 线路类

| # | 修改项 | MATSim 落地 | 要点 | 分期 |
|---|---|---|---|---|
| A1 | 新增线路 | transitSchedule（line/route/networkRoute/departures）+ transitVehicles（车辆实例）+ network（确保沿线 link 含 pt 模式） | 站间时分=Σ(link长度/运营速度)+停站时长；每班次生成一辆车 | P0 |
| A2 | 删除线路 / 单方向 | 删 transitLine 或其中一个 transitRoute；清理孤儿车辆 | — | P0 |
| A3 | 走向调整（局部改线） | 重建 networkRoute 与站序，重算 offsets；departures 保留 | 未修改的首尾段 offsets 尽量沿用母本实测值 | P0 |
| A4 | 截短 / 延长 | 同 A3（站序截断/追加） | — | P0 |
| A5 | 线路拆分（一拆二） | 原线删除 + 两条新 line（宏：A2+A1×2） | 断点站为两线共同端点 | P1 |
| A6 | 线路合并（二合一） | 两线删除 + 一条新 line（宏） | 走向自动衔接，需人工确认接缝 | P1 |
| A7 | 大站快车（skip-stop） | 同一 transitLine 下**新增一个 transitRoute**（跳站站序 + 独立 departures + 可独立车型） | 向导：选母线→勾选保留大站→给独立间隔 | P1 |
| A8 | 区间车（short-turn） | 同一 line 下新增截断站序的 transitRoute + 独立 departures | 向导：在母线上拖选区间 | P1 |
| A9 | 双向不对称班次（潮汐） | 两个方向 transitRoute 分别生成不同 departures | 间隔表单按方向分开 | P1 |
| A10 | 微循环 / 地铁接驳线向导 | 宏 → A1（环线走向模板：围绕选定轨道站自动寻径成环）+ 可选 S1 新站 | 纯交互增强，落地即普通新增线路 | P1 |
| A11 | 夜班线 / 服务时段模板 | A1 或 O2 的模板化（22:00–次日 6:00 等预设时段） | 跨零点 departures 用 >24h 秒数表达 | P1 |

### B. 站点类

| # | 修改项 | MATSim 落地 | 要点 | 分期 |
|---|---|---|---|---|
| S1 | 新增站点 | transitSchedule stopFacility（coord + linkRefId）；可选插入若干线路站序 | linkRefId 必须指向公交可行 link | P0 |
| S2 | 移动站点 | 改 stopFacility coord + 重吸附 linkRefId；引用线路 offsets 重算 | 跨 link 移动提示受影响线路 | P0 |
| S3 | 删除站点 | 从所有引用线路的站序中移除；无引用后删 facility | 不改线路几何（照走不停） | P0 |
| S4 | 合并站点 | 保留站吸收被并站的全部引用，被并站删除 | 名称/位置取保留站 | P1 |
| S5 | 站点更名 | stopFacility name | 纯展示层意义，仍保留 | P1 |

### C. 路网类

| # | 修改项 | MATSim 落地 | 要点 | 分期 |
|---|---|---|---|---|
| N1 | 新增路段 | network 增 node/link（length/freespeed/capacity/permlanes/modes） | 双向=两条反向 link | P0（首版可只做双向常规路） |
| N2 | 删除路段 | 删 link（成对处理双向） | 引用线路必须先处理（校验阻断）；背景车流靠全局重路由消化（§8.4） | P0 |
| N3 | 路段属性修改 | link 的 freespeed / capacity / permlanes | — | P0 |
| N4 | 公交专用道 | 方式A：平行 pt 专用 link + 原 link 容量折减；方式B：modes 去 car | A 更真实，B 更简单 | P1 |
| N5 | 单行方向调整 | 删一向 link / 补反向 link（宏：N1+N2） | — | P1 |

### D. 运营类

### 6.3 校验状态区

### 6.4 草稿（服务端持久化）

- 一个草稿 = 母本模型 + 研究区域 + 修改项列表 + 元信息，**自动保存**（防抖 2s 调 `saveDraft`），刷新/换机不丢。

## 8. 场景切分方案设计（核心）

> 回答"OD、站点、线路怎么切"。设计为两档模式。**用户决策（2026-07-03）：首版直接实现模式B（几何硬切）并作为默认**；模式A 作为文档层面的稳健备选保留，暂不实现。两档共享同一套"从母本 output 出发"的原则。

### 8.0 共同原则

1. **切分源是母本的 output，不是原始 input**：`output_plans`（含每人最终选中的、带完整路由与经历时间的计划）、`output_network`、`output_transitSchedule/Vehicles`、`output_config`。只有 routed plans 才能判断"谁的出行与区域有关、从哪儿过界、何时过界"。实现上用 MATSim 流式 API 读 plans（不依赖内存中已加载的模型，规避大模型 lazy 加载不读 plans 的问题）。
2. **plans 预清洗**：只保留 selected plan；把每个 trip 还原为"单一主模式 leg"（删除 pt interaction 活动与 access/egress 子 leg，清空 route 元素）——路由交给新场景的 it.0 重算。这一步同时解决"方案模型改了网/线后旧路由失效"的问题，并保证基线与方案从同一张白纸起步（公平性）。活动的时间、坐标、link 挂接与 person 属性（subpopulation 等）保留；person 的私家车辆记录（output_vehicles 中非公交车辆）随保留人群同步筛选。
3. **基线与方案共用切分结果**；config 完全一致（含随机种子），仅输入文件路径与输出目录不同；`controler.runId` 不设置（平台按 `output_*.xml.gz` 文件名解析结果，设 runId 会改文件名前缀）。
4. **评估口径**：切分模型的统计范围即研究区域（desc.json 记录区域多边形与面积），前端查看时天然是区域视角。

### 8.1 模式A · 需求相关保留（备选方案，暂不实现）

**思路：切"人"，少切"网"。** 运行时间主要随 agent 数与公交车次数下降，路网规模影响相对次要，所以第一版不做几何裁剪，避开一切边界手术。

| 对象 | 规则 |
|---|---|
| **人口/OD** | 遍历母本 routed plans，把人分四类：**全内**（所有活动在区域∪缓冲带内）→ 保留完整计划；**跨界**（部分活动在内）→ 保留完整计划（不截断！）；**穿越**（活动全在外但某条 leg 的路由几何穿过区域）→ 保留完整计划；**无关** → 删除。 |
| **路网** | 整张保留（不裁剪、不清理）。跨界/穿越者在区域外的行程照常仿真，只是无关背景车流消失了。 |
| **公交线路** | 保留：① 走向与"区域∪缓冲带"相交的线路；② 被保留人群的原路由使用过的线路（从清洗前 plans 的 pt route 引用统计）。其余整线删除。**保留的线路不截断**，时刻表原样。 |
| **站点** | 保留被保留线路引用的全部 stopFacility（含区域外的）；其余删除。 |
| **公交车辆** | 保留被保留 departures 引用的车辆与车型，其余删除。 |

- 优点：实现最简单、零边界伪影、切分结果绝对可靠；agent 通常降到全市的 10–30%（视区域而定），公交车次大幅下降，运行时间数量级改善。
- 缺点：场景仍偏大（长距离跨界者的全程都在仿真）；区域外公交被删后，跨界者在外段重路由可能改走保留线路/小汽车，存在轻微失真——但基线与方案同样失真，**对比仍然干净**。
- 缓冲带的作用：让"贴边"的线路与出行进入保留集，减少上述失真。

### 8.2 模式B · 几何硬切（P0 默认实现，追求最小场景）

在模式A分类基础上做边界手术，得到"只包含区域"的小模型：

| 对象 | 规则 |
|---|---|
| **人口/OD** | 全内：不变。**跨界**：沿母本路由找到过界点，把区域外部分折叠成一个 `outside` 虚拟活动，位置取过界 link/边界外第一个锚定公交站，`end_time`=母本中该人过界时刻（保留真实到发节奏）。**穿越**：折叠为 `outside→outside` 的过境 trip，进入时刻取母本过界时刻；默认保留 100%（可设采样率，用于控制背景流规模）。 |
| **公交线路** | 与区域无交集→删；有交集→**截断**：站序保留"区域∪缓冲带内的站 + 两端各外延 1 个锚站"；networkRoute 相应截断；departures 重建——以母本时刻表中"各班次到达新首站的时刻"为新发车时刻（保留全天频率与波动）。 |
| **站点** | 截断后被引用的站保留。 |
| **路网** | 保留：区域∪缓冲带内全部 link + 保留线路截断后走向经过的 link + 跨界/穿越者过界点附近的衔接 link；随后按模式跑连通性清理（car / pt 分别 MultimodalNetworkCleaner），活动/站点的 link 挂接重新吸附到保留路网。 |

- 优点：场景最小、运行最快，真正"限定在研究区域"。
- 缺点：工程复杂度高（过界点计算、时刻表重建、连通性修复都有坑），边界活动的时间固定假设会压制"出行时间调整"这类行为反应。

#### 8.2.1 边界方式锁定（用户硬性要求，2026-07-03）

**跨界/穿越出行在边界处不允许改变出行方式**：坐公交进区域的人不能在边界"突然"换成开车/骑电动车，开车进来的人也不能突然上公交。实现设计：

1. **折叠时保持主模式**：跨界 trip 折叠后的 leg，其 mode = 母本中该 trip 的主模式（routingMode），不做任何替换；
2. **仿真中锁定方式创新**：被折叠的人（跨界+穿越）划入派生子人群——对母本每个原子人群 `s`（含默认空子人群）生成 `s__bLock` 派生名，person 的 subpopulation 属性改写为派生名（原值另存 `origSubpopulation` 属性备查）：
   - config `replanning` 中为每个派生子人群仅配置 **ChangeExpBeta（选择）+ ReRoute（重路由）**，**不配置任何方式创新策略**（SubtourModeChoice / ChangeSingleTripMode 等），也**不配置时间突变**（TimeAllocationMutator）——保证过界时刻锚定不漂移；
   - config `scoring` 中把原子人群 `s` 的 scoringParameters 整块克隆为派生子人群同名参数集（评分行为与原人群一致）；
   - 全内 agent 保持原子人群与母本全套创新策略（方式/时间/路径均可调整）——这正是方案要捕捉的行为反应。
3. **路径仍然自由**：锁的是"方式"不是"路线"——公交乘客可换乘别的线（这正是评估新线吸引力所需），司机可绕行新路。
4. **outside 虚拟活动**：新增活动类型 `outside`，config 中补 activityParams（typicalDuration=12h、`scoringThisActivityAtAll=false`），不参与打分、不产生失真激励。
5. **锚点合法性后校验**：网络裁剪完成后复核每个 outside 活动的挂接 link 仍存在且允许对应模式（car 折叠点须为 car 可行 link，pt 折叠点吸附到保留站点），失效者就近重吸附。

### 8.3 模式选择说明（UI 文案）

- 首版仅提供模式B（几何硬切+边界方式锁定），无需用户选择；切分模式作为 desc.json 元数据记录 `"cutMode": "B"`；
- 无论哪种模式，**结论都来自"切分基线 vs 切分方案"的相对比较**。

### 8.4 config 派生细节

- 从 `output_config.xml` 复制后修改：五个输入路径、`controler.outputDirectory`、`lastIteration`（向导值）、坐标系原样、replanning 策略原样（保证与母本行为一致）、`qsim` 线程数按运行机配置模板覆盖；
- 建议默认在 80% 迭代处关闭创新策略（fractionOfIterationsToDisableInnovation，若母本未设置则补上）以促收敛；
- 两模型 config 逐字节一致（除路径），随机种子相同。

## 9. 修改应用引擎（编辑项 → MATSim 文件变换）

### 9.1 应用顺序（固定，保证依赖正确）

```
路网类(N*) → 站点类(S*) → 线路类(A*) → 运营类(O*) → 政策类(P*)
```

同类内按清单创建顺序执行。每项应用后做增量一致性检查，任何一步失败即中止并在校验报告定位到具体修改项。

### 9.2 关键生成算法

- **新增线路的 networkRoute**：在"公交可行子网"（link.modes ∋ bus∪car，方案模型含新增路段）上按用户锚点做最短路寻径；生成阶段直接复用编辑期 `snapRoute` 的确定结果（草稿里存的是 link 序列而非裸坐标，避免两次寻径不一致）。
- **站间时分（offsets）**：`arrivalOffset(k) = Σ link长度 / min(freespeed, 运营车速)` 逐站累加，`departureOffset(k) = arrivalOffset(k) + 停站时长`；修改既有线路时，未触碰区段沿用母本 offsets，仅重算受影响区段并顺延。
- **departures 生成**：按（时段,间隔）表展开为发车时刻序列；每班次创建车辆实例 `veh_{route}_{seq}`，引用指定车型；修改间隔=删旧班次与孤儿车辆后重建。
- **公交专用道（方式A）**：为选中 link 序列创建平行 link（同 from/to 节点、modes=pt、permlanes=1、capacity≈1800、freespeed=原值），原 link capacity×(n-1)/n；沿线线路的 networkRoute 改走新 link，站点 linkRefId 迁移。
- **删除路段的背景交通**：由于 §8.0 已全局清空路由，方案模型 it.0 会自动绕行，无需逐 agent 修补。

### 9.3 产物与留档

```
<模型目录>/
├── input/           # 五件套 + 可能的附属文件
├── edits.json       # 应用的全部修改项（含参数与吸附结果）
```

## 10. 运行、进度与结果注册

### 10.1 运行机制

- **独立进程运行**：由后端 `RunJobManager` 以 `java -Xmx<配置> -cp <matsim-runner.jar> ...RunScenario <config>` 启动子进程（仓库内新增一个薄 runner 模块打 fat jar，MATSim 版本与后端一致 2025.0-PR3653）。不在 API 服务 JVM 内跑，避免拖垮平台。
- **队列**：全局 FIFO，默认并发 1（配置项）；一个 Job = [切分 → 应用 → 校验 → 运行基线 → 运行方案 → 注册]，六阶段。用户可取消（杀子进程 + 清 staging）。
- **落盘策略**：全过程在 `仿真数据/<scope>/_staging/<jobId>/` 下进行，**成功后原子移动**到正式目录 `仿真数据/<scope>/<模型名>/`——保证模型扫描永远不会看到半成品（`_` 前缀目录被扫描器忽略）。

### 10.2 进度与展示

- 复用平台成熟的"轮询 + 状态对象"模式（与 cacheStatus 同款）：`POST /pt/optimization/jobStatus` 返回 `{stage, percentage, message, iteration, lastIteration, etaSeconds, logTail[]}`；运行阶段进度 = 解析 output 目录 `scorestats.csv` 行数 / lastIteration，日志尾部随带。
- 右侧"运行任务"区：本人任务卡片（六阶段 stepper + 迭代进度条 + 展开看日志尾部）；失败卡片给"查看日志 / 重试 / 清理"。任务状态持久化到 staging 目录 JSON，后端重启后可恢复展示（运行中的进程标记为中断，允许一键重跑）。

## 14. 校验规则清单

**前端轻量（清单变更即时）**

- 区域多边形自相交 / 面积为 0；
- 新增线路 < 2 个停靠站；发车间隔/时段表重叠或为空；首末班倒挂；
- 引用完整性：edit 引用的新建对象仍在清单中（依赖图闭合）；
- 目标要素越出研究区域（警告）。

**服务端全量（生成向导 Step 2 / `validate` 接口）**

- 阻断类：删除的 link 仍被某线路 networkRoute 使用且无对应改线项；新增站点吸附的 link 不允许 pt；新增线路寻径不连通；stopFacility linkRefId 悬空；departures 引用车型不存在；模型重名；磁盘剩余空间 < 预估需求；
- 警告类：删站后某线路相邻站距 > 2km；专用道折减后 link car 容量为 0；分时段间隔造成同刻并发发车 > 车队合理规模；修改项目标在切分后不存在（区域改动导致）；方案与基线完全一致（无有效修改）。

## 16. 关键决策与风险

| # | 决策/风险 | 说明与对策 |
|---|---|---|
| 1 | **切分默认并仅实现模式B**（用户决策 2026-07-03） | 附带硬性约束：边界方式锁定（§8.2.1）；模式A 降为文档备选 |
| 2 | **从 output_plans 流式切分** | 母本必须有 output_plans；`cuttable` 校验前置到模型下拉。流式读避免 20GB 大模型内存问题 |
| 3 | **全局清空路由、统一重路由** | 公平对比的代价是需要足够迭代数（默认 100）；运行时长预估要如实展示 |
| 4 | **独立进程 + 单并发队列** | 平台 API 与仿真进程隔离；本机 USB 盘开发环境资源有限，默认并发 1，服务器部署可调 |
| 5 | **staging + 原子移动** | 模型扫描永不见半成品；失败残留由清理任务回收 |
| 6 | **不设 runId** | 平台按 `output_*.xml.gz` 命名解析，保持默认命名 |
| 7 | **公开目录写权限** | 用户决策(2026-07-03)：暂不需要审核，任何登录用户可直接保存到 public（接口保留 scope 校验点以备将来收紧） |
| 8 | **磁盘空间** | 生成前预估（母本 output 尺寸 × 切分比例 × 2）并校验剩余空间，不足则阻断 |
| 9 | **修改项作用于切分后的场景** | 编辑时的底图是母本全网，生成时若目标被切掉（理论上不会——目标都在区域内），校验兜底为警告并跳过 |
| 10 | **可移植性（用户要求 2026-07-03）** | 仓库自包含：runner（MatsimScenarioRunner）是后端代码的一部分，用后端进程自身的 JVM 与 classpath 启动子进程；dev（spring-boot:run）走 -cp，fat-jar 部署走 Spring Boot PropertiesLauncher（已实测）。git pull + mvn package 后任意机器可跑，无仓库外依赖 |
