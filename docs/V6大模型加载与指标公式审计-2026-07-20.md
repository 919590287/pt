# V6 大模型加载、轨迹缓存与指标公式审计（2026-07-20）

## 结论

本轮已完成轨迹、缓存替换、数量口径、评价指标和大块传输的系统修复。核心结论如下：

1. **不会再因 `desc.scale` 或所谓抽样比例改变模型数量。** 人口、人次、出行、换乘、走廊和评价指标均按已加载模型原始量 1:1 计算；缺能力或缺数据分别返回 `unsupported` / `nodata`。
2. **小汽车等非公交车辆能够进入轨迹缓存和默认显示。** 大模型轨迹几何从完整 network 流式索引，不再受内存中的公交裁剪子网限制；events 引用未知 link 时拒绝发布不完整缓存。
3. **缓存重建不再追加到旧缓存。** 当前版本目录在重建前清空，成功后删除同族旧版本；面板派生缓存与乘客分区使用临时目录完整写入后替换固定正式目录。
4. **228 MB 级单块和 Worker 全量复制路径已移除。** 新格式使用 30 秒存储容器、10 秒播放窗口、1～2 秒跳转快照和 4096 m 空间索引；主线程直接转移 `ArrayBuffer`，Worker 使用有字节上限的 LRU，浏览器持久缓存按 generation 隔离。
5. **评价公式已改为严格公交口径。** 公交、地铁不再混算；缺分母、坐标系不明、制式无法判定或标准定义不充分时，不再输出貌似精确的零值或部分真值。

仍有三个需要明确的工程边界：全新 V6 首次分析缓存仍应作为后台预生成任务；极端密集的全市精确 10 秒请求不做抽样或截断，响应仍可能较大；“标台数”目前是高峰同时在营车辆估算值，不是经车辆折算系数认证的统计年报值。

## 一、问题与修复对应

| 用户要求 | 原风险 | 已实施结果 |
|---|---|---|
| 小汽车等轨迹缓存和显示 | 大模型运行时只保留公交子网，汽车 link 可能找不到；前端默认只看公共交通 | 轨迹单独流式读取、转换完整 network；默认 `all`；未知 link 直接失败，不发布部分缓存 |
| 重建直接替换旧缓存 | 分片原位写入可能残留旧文件；源指纹目录不断新增；浏览器可能继续命中旧 generation | 版本目录重建前清空；固定正式目录替换；成功后删除旧版本；前端按 `loadVersion/cacheGeneratedAt` 清浏览器模型缓存 |
| 线网密度和抽样比例 | `scale` 扩样造成数量失真；面积/几何缺失时可能猜测或下发零值 | `scale` 恒为 1；加载多少计算多少；面积优先采用真实数据行政区边界的投影面积，并随行政区切换；边界缺失才回退显式 `desc.area` |
| 时间/空间小块、播放丝滑 | 5 分钟全市块最大约 228 MB；Worker 全量持有/复制；拖动需要载入大块 | 30 秒容器 + 10 秒视口块 + 1/2 秒快照；空间索引精确筛选；传输所有权、LRU、预取、取消过期请求 |
| 核对公式 | 公交/轨道混算、leg 代替 trip、几何直线代替 link.length、错误分母、缺失数据伪零 | 统一在 `TransitMetrics` 和 evaluation-v5；严格完整性与口径元数据；不可靠指标显式 unsupported |

## 二、V6 加载与轨迹性能证据

### 2.1 基础模型加载实测

以下数据来自同一台 24 GB 本机、JDK 21、外置卷上的既有 V6 实测：

| 项目 | 结果 |
|---|---:|
| 基础模型冷载（首次生成配置兼容文件与公交裁剪子网） | 10.019 s |
| 热载，限制 `-Xmx320m` | 2.738 s |
| 热载后 GC 已用堆 | 约 227.2 MB |
| 完整 network | 1,048,576 links |
| 运行时公交裁剪子网 | 168,007 links、142,473 nodes |

基础加载已不需要把完整路网、两份 300～400 MB 解压面板和 2,063.9 万条乘客明细同时对象化。完整 network 只在需要的离线构建器中流式或临时读取。

### 2.2 旧轨迹块实测与方案选择

旧 `trajectory-v9` 的 V6 工件实测为：

| 项目 | 旧 5 分钟块 |
|---|---:|
| 文件数 | 337 |
| 总体积 | 17.5765 GiB |
| p50 | 37.5967 MiB |
| p95 | 176.3233 MiB |
| 最大 | 217.5925 MiB（约 228.16 MB 十进制） |

把同一批 v9 数据**仅按时间**投影成 30 秒块的扫描结果为 3370 个文件、24.0423 GiB，p50 4.7864 MiB、p95 22.7292 MiB、最大 28.7100 MiB。虽然 p95/最大块约下降 87%，但跨边界线段重复使总体积反而增长，所以最终没有采用“只切时间”的方案。

新 `trajectory-v14` 采用以下结构：

- 存储：每 30 秒一个 `.bin` 容器和一个 `.idx`，避免海量小 tile 文件。
- 播放：每次只返回固定对齐的 10 秒窗口；30 可被 10 整除，不跨存储容器。
- 跳转：快进/拖动先取固定对齐的 1 秒或 2 秒快照，随后预取的 10 秒块接管连续播放。
- 空间：4096 m WebMercator 网格；每条线段只按中点归属一个 tile，不重复存储。
- 精确性：索引记录每个 tile 内全部线段的真实聚合包络，候选读取后再做逐线段包围盒判断；空间裁剪是视口查询，不是统计抽样。
- 全市统计：每秒车辆数/均速等 `globalStats` 独立保留，地图只加载视口线段不会改变全市指标。
- 并发：过期请求可取消，响应带 generation/ETag；Worker 和 IndexedDB 都有容量上限与淘汰策略。

这轮没有对 15 GB events 执行一次最终 v14 的完整 V6 重建，因此不能把上面的 v9 扫描投影写成 v14 的实际最终磁盘体积。可确认的是响应上限已从“全市 5 分钟”降为“视口 10 秒/快照 1～2 秒”，且统计数量没有抽样。

### 2.3 首次加载边界

V6 原始 events 约 15.02 GiB、plans 约 14.40 GiB。一个完全没有派生缓存的新模型，首次轨迹、人口、出行和面板构建仍需完整扫描这些文件；历史测量/估算约为 23～31 分钟，本轮没有重新执行最终 v14 全量构建。正确业务方式是：

- 上传或注册后后台预生成；
- 页面轮询 `generating/deferred`，不让第一个用户同步等待；
- 构建机保证外置卷稳定、空间充足；
- 发布后优先做一次 V6 烟雾验证，再开放给普通用户。

## 三、轨迹正确性

### 3.1 小汽车为什么现在不会丢

基础模型为节省堆只保留公交 schedule 引用的子网，这适合大部分公交分析，但不能作为全方式车辆轨迹的几何来源。新轨迹构建器用 `MatsimLinkGeometryIndex` 单独流式扫描完整 network，并按配置声明的 CRS 转成 EPSG:3857；汽车、货车、DRT 等只要 events 中存在合法 link，就与公交车辆一样生成线段。

质量闸门如下：

- events 的进入/离开 link 必须能在完整 network 中解析；
- 源 network 坐标转换出现非有限值时，中止模型发布；
- 小模型和大模型都执行相同的未知 link 拒绝策略；
- generation 指纹包含 events、network、schedule、transit vehicles、config 和 plans，任一来源变化都会失效；
- `.bin/.idx` 缺失或校验失败会标记当前 generation 损坏，下一次由单飞锁重建，旧工件不会继续被当作 ready。

### 3.2 快进、拖动与播放

前端保持原交互语义：

1. 正常播放使用当前与相邻 10 秒块自适应预取；
2. 时间轴随机跳转先显示 1～2 秒快照，避免等待大块；
3. 视口小幅移动仍落在相同量化网格时复用 HTTP/IndexedDB 缓存；
4. 跨网格时请求新窗口，旧请求通过序号和 `AbortController` 失效；
5. `ArrayBuffer` 直接转移给 Worker，主线程不再保留同一份轨迹数组；Worker 仅保留受字节预算约束的热点块。

## 四、缓存替换语义

### 4.1 已保证的语义

- 轨迹、人口、出行、换乘、走廊、速度、画像、线路/站点面板、完整路网派生等版本缓存，重建前清空当前正式版本目录，不在旧分片后追加。
- 成功发布后删除同组件其他 `*-vN` 目录，磁盘最终只保留一个正式版本。
- `panel-read-v2` 与乘客明细分区先在随机临时目录完整写入 manifest，再替换固定目标目录；源变化不再不断创建新指纹目录。
- manifest 最后发布；没有 ready manifest 的半成品不会被读取。
- 浏览器模型数据缓存同时绑定后端 `loadVersion` 与 `cacheGeneratedAt`，任一 generation 改变即清除旧数据。

### 4.2 可用性边界

多数大型组件采用“删除当前版本目录后原位重建”，满足“不新增、直接替换”和不混入旧分片，但不是双目录指针切换式的零停机发布。重建窗口内接口会返回 `generating/deferred/202`。如果未来要求缓存重建期间仍持续供应旧 generation，需要另做“双 generation + 原子 current 指针”的磁盘空间换可用性方案。

## 五、数量、密度与缺失态

### 5.1 数量政策

平台统一写入 `quantityPolicy = model-original-no-sampling-no-scaling`：

- `MatsimData.scale` 永远为 1，setter 不接受历史配置改变；
- scheme、注册、接口和前端展示均固定 1:1；
- 人口栅格、出行端点、OD、换乘、走廊、客流和评价分子/分母不做扩大或缩小；
- 轨迹空间视口筛选只减少传输范围，不改变全市统计，也不是随机抽样。

部分地图工件为控制展示规模会披露 Top-K 或被截断的低量 OD 对，但其总量 summary 和评价指标不使用截断结果。

### 5.2 `unsupported` 与 `nodata`

| 状态 | 含义 | 示例 |
|---|---|---|
| `unsupported` | 当前模型/加载模式没有计算该指标所需能力，或业务定义不足 | 未加载 plans、CRS 不可识别、legacy `pt` 无法判定公交/轨道、缺场站面积定义 |
| `nodata` | 计算方法受支持，但模型中没有有效样本/分母 | 无有效 home、无公交站、无发班、部分路线缺 link 导致严格全网值不能形成 |
| `ready` | 口径完整且值可对账 | 同时返回公式版本和有效/缺失样本元数据 |

密度不再用站点凸包或猜测面积。优先读取模型所在城市
`真实数据/行政区范围` 的真实边界，以 EPSG:32649 投影计算面积；常住人口按
`population-v9` 的 home 栅格中心落区，公交物理路段按行政区边界精确裁切。
全市与 11 个区一次预计算并落盘，切换行政区只读对应缓存；真实边界缺失时才回退
`desc.area`。坐标转换失败的点会置空并计数，不会把原坐标继续冒充 EPSG:3857。

## 六、评价指标公式审计

评价接口版本为 `evaluation-v13`，人口缓存为 `population-v9`，可视化预计算为 `visual-v25`。道路公交范围固定为 `bus/trolleybus/brt`；泛化 `pt` 只有能由 `TransitPassengerRoute + schedule` 明确解析时才计入。小模型和大模型均在模型加载阶段生成上述缓存，体检评估和总览请求只读取缓存，不在请求线程扫描 `plans/events`。

| 指标 | 当前公式/状态 | 完整性规则 |
|---|---|---|
| 常住人口密度 `czrkmd` | 当前行政区边界内、plans 中具有有效首个非 stage `home/home_*` 位置的常住人数 ÷ 同一边界投影面积 km² | home 位置先缓存为 100 m 栅格并以栅格中心落区；全市分子同样裁到全市真实边界 |
| 线网密度 `gjxwmd` | 当前行政区边界内的公交道路中心线无向全局去重长度 km ÷ 同一行政区边界投影面积 km² | 依据 JT/T 1457—2023 的分子定义；按业务确认暂以行政区总面积代替公交适设区域面积。跨区 link 按边界裁切比例分摊，双向 node pair 去重取有效最大 link.length |
| 300m 覆盖率 `fgl300` | 首个有效非 stage `home/home_*` 在任一公交站地面 300m 内的人数 ÷ 有有效 home 人数 ×100% | 披露总人数、有效 home、缺失 home、转换失败；未知 CRS 或站点转换失败为 unsupported |
| 万人保有量 `wrbyl` | 按国家标准车长系数折算的计划运营公共汽电车标台数 ÷ 常住人口 ×10000 | 车辆 ID 按全天公交计划班次去重；车辆或车型车长不完整时不猜值 |
| 公交分担率 `cxfdl` | 公共交通主方式完整 OD 出行数 ÷ 机动化主方式完整 OD 出行数 ×100% | 按 trip 不按 leg；步行、自行车及接驳步行不进入分母 |
| 平均日载客量 `cjrzkl` | 公交上车人次 ÷ 全天计划运营公交车辆 ID 去重数 | 与运行监测采用同一公交上车人次和运营车辆口径 |
| 单班次载客量 `dbczkl` | 公交上车人次 ÷ 公交日发班数 | 只计道路公交 |
| 日出行次数 `rcxcs` | 常住人口公交主方式完整 OD 出行数 ÷ 有有效首个 home 的常住人口 | 明确排除地铁、铁路与轮渡；缺完整出行链或 home 分母为 unsupported |
| 线路非直线系数 `xlfzxxs` | 先按线路取各运行方向平均里程，再除以首末站地面直线距离，最后对非环线路等权平均 | 同线路分时 profile/相同几何不重复加权；同端点式线路 ID、环线标记、闭合几何及首末距离≤线路里程10%的近环线排除；同时披露最大值、>3.0 异常线路数及 ID |
| 线路重复系数 `xlcfxs` | 各公交线路方向平均长度之和 ÷ 无向去重公交物理道路长度 | 同方向分时 profile 和相同几何去重；统一使用 link.length，缺路线几何为 nodata |
| 公交/汽车速度比 `yxsdb` | 高峰公共汽电车 `Σ班次运营里程/Σ班次行程时间` ÷ 高峰小汽车 `Σ行程距离/Σ行程时间` | 早晚高峰 7:00–9:00、17:00–19:00；公交行程时间含沿途停站；模型未标记“应设置公交专用道道路”，小汽车空间范围暂用模型城区全部道路并在元数据披露 |
| 平均候车时间 `pjhcsj` | `mean(boardingTime - leg.departureTime) / 60` | 只接受可解析的道路公交和非负可靠样本 |
| 高峰满载率 `xlmzl` | 每个早晚高峰公交班次先取最大站段在车人数/额定载客量，再对全部有效高峰班次等权平均 ×100% | 高峰窗 7:00–9:00、17:00–19:00；任一高峰班次缺车辆或容量则不下发部分真值 |
| 线路客流强度 `xlklqd` | 全网公交上车人次 ÷ 全网计划运营车公里 | 计划运营车公里=`Σ线路里程×发班数`；与线路监测共用道路公交上车口径 |
| 平均换乘次数（公交） `pjhccs` | 含公交乘坐段的完整 OD 出行内换乘总次数 ÷ 全部含公交乘坐段的完整 OD 出行数 | 换乘次数=公共交通乘坐段数−1，公交—公交及公交—轨道等均计入；不使用已发生换乘的子集作分母 |
| 公交—轨道接驳比例 `gjjbbl` | 同时含公交与轨道乘坐段的完整 OD 出行数 ÷ 全部含公交乘坐段的完整 OD 出行数 ×100% | 由 population-v9 流式扫描 plans 缓存，大小模型共用 |
| 车均场站面积 `cjczmj` | 仿真模式：**unsupported**；真实模式：公交场站 `F004` 用地面积总和 ÷ 真实运营车辆去重数 | 仿真模型缺场站面积；真实模式缺面积或车辆分母时返回 null |

评价指标框架参考现行国家标准 GB/T 35654—2017《城市公共交通发展水平评价指标体系》和交通运输行业标准 JT/T 1457—2023《公共汽电车线网评价指标》。每项指标同时落盘保存分子、分母、有效样本数或缺失原因，避免只下发无法对账的结果值。

真实模式使用同一组规范公式（`evaluation-v13-real-v2`），不采信接口中的旧预计算比值，也不以替代指标补缺。常住人口密度的分子按业务要求改取
`真实数据/职住人口/广州市百米网格职住人口_WGS84.csv` 的“常住人口数量”，面积取同范围行政区面积；车均场站面积的面积分子取
`真实数据/公交场站` SHP 的 `F004`“用地面积(㎡)”字段总和。缺少小汽车速度、车辆额定容量、车型车长或全方式出行链等规范分母的指标保持
`unsupported`，不输出部分真值。

### 6.1 线路非直线系数异常核查（2026-07-28）

按 `visual-v24` 新口径对当前广州 V6 时刻表与路网实算，旧缓存值 **3.09** 降为 **2.00**（未四舍五入值 1.9978）。旧值偏高的主要原因是环线未完整排除，以及同一线路的分时 profile/route 变体被重复加权。新结果纳入 1302 条非环公交线路，排除 364 条环线 route；仍有 81 条非环线路系数大于 3.0，最大值 9.69，对应线路 `900000044087@900000044088`。这些剩余异常候选保留在总体均值中，并通过 `abnormalNonLinearLineIds` 下发供核查源线路绕行或端点数据，不以删异常值方式美化结果。

## 八、上线注意事项与剩余风险

1. **必须预构建一次新版本。** 当前外置卷里的旧 V6 缓存版本不会被当作新版本 ready；部署后会生成 `trajectory-v14`、`visual-v17`、`population-v5` 等新工件。
2. **不要把 23～31 分钟写成页面首次加载时间。** 这是全新大文件分析缓存的后台构建量级；基础模型已有冷/热载秒级实测。
3. **磁盘容量需在正式 V6 v14 重建后复测。** 设计保证线段不因空间 tile 重复存储，但最终压缩率和 index/container 比例必须以真实 v14 工件为准。
4. **精确性优先于极端响应上限。** 为遵守“不允许抽样”，服务端没有对单个极密集 10 秒视口做车辆数截断；极端全市视口仍可能产生较大 `byte[]`。V6 正常 10 秒投影远小于旧 228 MB 块，但未来更密模型可考虑精确分页协议，不能静默采样。
5. **重建期间存在短暂不可用窗口。** 当前是删除正式目录再重建，不会追加污染，但也不是零停机双 generation 切换。
6. **标台是估算口径。** 若业务需要与统计年鉴严格比较，应补充车辆折算系数/真实车队台账，再升级公式版本。
7. **构建产物仍有大包提示。** Vite 成功，但地图/图表主包仍有 >500 kB 警告；这不影响本轮轨迹正确性，后续可继续路由级拆包。
