# 公交出行监测 · 人口分布监测 设计方案

2026-07-15 定稿。运行监测页新增第一个监测模块「公交出行监测」，置于「总体客流监测」（原「总体客流变化」，本次改名）之前；首个子模块「人口分布监测」。

## 1. 需求口径

- 展示模型人口的空间分布，居住人口 / 就业人口可切换：
  - **居住人口** = MATSim plans 中每人 selectedPlan 里第一个 `home*` 活动的坐标；
  - **就业人口** = 第一个 `work*` 活动的坐标（无 work 活动的人不计入就业人口）。
  - 活动类型匹配规则：`type.toLowerCase().startsWith("home"|"work")`，跳过含 `interaction` 的中转活动。
- 地图用 **100 米栅格**表示分布，配色为密度分级（人/km²，见 §4 分级）；叠加**街道级行政边界**描边与「街道名 + 占比%」标注（占比 = 该街道人口 / 当前显示范围人口）。
- 右侧面板：当前显示范围（行政区联动）内按街道排列的人口数与密度榜单，随居住/就业切换。
- 计数口径与换乘分析一致：**缓存存抽样量，前端 ÷scale 扩样展示**。

## 2. 后端架构（population-v1）

新增 `data/cache/MatsimPopulationCache.java`，模式完全照 `MatsimTransferCache`（per-model `ModelBuildLocks`、manifest.json 源指纹、原子落盘、MEMORY_CACHE 记忆化）。工件目录 `cacheFolder/population-v1/`：

| 工件 | 内容 |
| --- | --- |
| `population-summary.json` | status/cacheVersion/generatedAt/scale/cellSizeMeters=100/mercCellSize/gridCells/persons/homePersons/workPersons/unassignedHome/unassignedWork/homeTypes/workTypes |
| `population-grid.bin` | 二进制栅格表（§3） |
| `population-streets.json` | `{ streets:[{code,name,district,areaKm2,home,work}], totals:{home,work} }`，176 街道全量（含 0 值） |
| `manifest.json` | status + cacheVersion + sources 指纹（plans 文件 + 街道资源版本） |

数据来源：

- 非大模型：`data.getPopulation()`（坐标已被 Datasource 统一转换到 globalCRS=EPSG:3857）。
- 大模型（plans 未常驻）：`StreamingPopulationReader` 流式读 `outfile.getPlans()`，坐标转换按 `Datasource.ctf(globalCRS, cfg.plans().getInputCRS(), population属性CRS)` 同源逻辑；population 级 CRS 属性在首个 person 回调前已可读。
- selectedPlan 为空回退 `getPlans().get(0)`（照 ScenarioCutService.processPerson）。

栅格：EPSG:3857 平面上 `mercCellSize = 100 / cos(centerLat)`（centerLat 取模型中心反算纬度），cell 索引 `i=floor(x/cs), j=floor(y/cs)`。

街道归属：内嵌资源 `resources/geo/gz_streets_wgs84.geojson.gz`（广州 176 街道，WGS84，属性 code/name/district/areaKm2），构建时转 3857 建 STRtree + PreparedGeometry 做点面归属；全部未命中的点计入 unassigned。

接入点：`Datasource.loadEvent` 在 `MatsimTransferCache.prepareOnModelLoad` 之后追加；`ModelCacheManager` 照 `transferCacheVersion` 的全部出现位置对称登记 `populationCacheVersion`。

## 3. grid.bin 二进制契约（前后端共同遵守，小端）

```
header: magic "PGRD"(4B) + version u16(=1) + count u32 + mercCellSize f64   // 共 18B
record × count（16B/cell，行式）: i i32, j i32, home u32, work u32          // 抽样人数
```

cell 西南角 = `(i*cs, j*cs)`，东北角 = `((i+1)*cs, (j+1)*cs)`（EPSG:3857）。

## 4. API（照 TransferController 模式）

| 端点 | 说明 |
| --- | --- |
| `POST /pt/population/summary` `{datasource}` | summary JSON；未就绪 `{status:"generating"}` |
| `POST /pt/population/streets` `{datasource}` | 街道统计 JSON；未就绪 generating |
| `GET /pt/population/grid.bin?datasource=&v=` | ETag/immutable（照 transfer events.bin），未就绪 404 |
| `GET /pt/population/streets.geojson` | 模型无关街道面资源，预压缩 gz 直出（Content-Encoding: gzip）+ ETag |

前端密度分级（人/km²，随居住/就业共用）：`500 / 1500 / 3000 / 5000 / 10000 / 20000 / 30000 / 40000`，九级绿→黄→红（对齐样张 res_desent 图例）。cell 密度 = 抽样数 ÷ scale ÷ 0.01km²。

## 5. 前端结构

- `runMonitorMenuItems` 首位插入 `公交出行监测`（children: `人口分布监测`），沿用 pfa 子菜单展开机制；「总体客流变化」改名「总体客流监测」。
- 新组件 `views/datavisualization/components/RKFB.vue`（run-monitor-mount 按 tab 挂载，`:key` 随模型）：
  - 拉 summary（generating 轮询）→ 并行拉 grid.bin + streets + streets.geojson；解析结果经 `modelDataCache.getModelDerived` markRaw 缓存。
  - 地图：deck.gl `GridCellLayer`（id `rm-population-grid`，经 `setSharedDeckLayer` 挂共享 overlay，interleaved 下 id 即样式层 id，满足 rm- 前缀契约）；maplibre 街道描边+标注（`rm-population-street-*`）。
  - 右侧面板 teleport 到 index.vue 容器（照 TJFX），含居住/就业切换、范围总人口、九级密度图例、街道榜单（数值 ÷scale 扩样、密度按街道面积，点击行地图定位街道）。图例实现时并入右侧面板（而非地图左下浮卡）：与切换/榜单同一视线，且免去悬浮层与地图控件的躲避逻辑。
  - GridCellLayer 的 cellSize 按 summary.cellSizeMeters ×1.02：fp32 实例定位抖动会在整齐栅格上留出发丝缝，2% 重叠肉眼不可见（独立渲染试验页已验证）。
- 行政区显示范围联动：面板榜单/街道标注占比按 displayRange 过滤，区外街道边界与标注淡化；栅格图层 P0 不裁剪（全市展示）。
- 本模块页签下线网瓦片与站点底图整体退场（照车辆运行监测的 shouldLoadTransitNetworkForCurrentTab 机制）。

## 6. 验证

- 后端：bin 布局回写读取、home/work 提取规则、栅格分箱、街道点面归属（用资源自身 interiorPoint）、街道资源完整性（176/南沙9）单测；小母本冒烟（`-Dpopulation.smoke=true`）。
- 前端：vite build + 解析器单测；浏览器冒烟（模块切换、图层挂卸、切换指标、行政区联动）。
- 跨栈对账：streets.json 的 home 总和 + unassignedHome == homePersons；前端解析 grid.bin 总和与 summary 一致。

## 7. 实施结果（2026-07-15）

双端已实现并验证：后端 10 项单测 + 全量回归 95 通过；小母本冒烟内存/流式双通路三工件逐字节全等（45686 人 / home 5611 / work 8486 / 2324 cell）；前端 vite build + 75 vitest（含 9 项 bin 契约测试）；跨栈对账 8/8 全等（前端解析器直读后端真实工件）；GridCellLayer 二进制属性渲染经独立试验页目验（九级配色/拼接/空洞/发丝缝修复）。8090 已重启换新 jar，4 端点经 OpenAPI 确认注册，ModelCacheManager 后台自动为既有方案补建 population-v1（小方案毫秒级）。**登录墙内人工回归待做**：模块切换/生成中轮询/指标切换/行政区联动/街道点击定位/streets.geojson 响应头（Content-Encoding: gzip 不被二次压缩）。
